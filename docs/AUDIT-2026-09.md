## 4. Message-market fit issues

1. **Buyer is under-specified.** Title says 50-500 employees, eyebrow says "Enterprise", `ANALYTICS_SPEC_2026_07.md` says the two ICPs are SMB Head of HR (50-500) and PE portco HR ops (200-2,000). Nothing on the page speaks to a PE operator.
2. **No compliance outcome above the fold.** The product's real differentiator (risk triage, statute-aware answers, audit trail, federal + 11-state jurisdiction data in `lib/data/jurisdictions.js`) appears only as a feature card halfway down.
3. **No coverage proof.** The repo holds a real jurisdiction table (Federal + CA, NY, TX, IL, CO, WA, MA, NJ, FL, GA, PA), 18 pre-mapped policy topics and a 10-item regulatory update feed with sources. None of it is shown.
4. **Emoji as UI.** Nav mark is `⚡`; every feature/problem card uses an emoji icon. `HOMEPAGE_REDESIGN_2026_CONCEPTS.md` §2 ranks this the #1 "poor man's HR tech" tell.
5. **Default dark-blue gradient hero, centered two-CTA card** — the #2 tell in the same document.
6. **Integrations are invisible.** Four real read-only payroll/HRIS syncs exist in `lib/payroll/providers/` (Gusto, BambooHR, QuickBooks Payroll, Finch → ADP/Paychex/Paylocity/UKG). The page never mentions them.
7. **`llms.txt` makes claims the security page explicitly denies**: `SOC 2 Type II certified, 256-bit AES encryption, GDPR compliant` and `Channels: Slack, Microsoft Teams, email, embedded web widget`. `/security` says SOC 2 is not done; the founding-customer section says Slack/Teams are roadmap. An answer engine quoting `llms.txt` would misrepresent the product.
8. **Unverifiable stats in the problem section** (`73% of HR questions are repeats`, `1,200+ employee inquiries per month`, `20% of new hire turnover happens in the first 45 days`) with a vague `(SHRM, industry reporting)` attribution.
9. **Pricing bullets drift between three sources.** Landing page, `lib/data/plans.js` and `llms.txt` disagree (e.g. llms.txt promises "Slack + Teams" on Professional and "dedicated CSM" on Enterprise; neither exists in `plans.js`).

## 5. Conversion / funnel gaps

- Primary CTA `Start Free Trial →` goes to `/sign-up`; the nav CTA goes to `#final-cta` (an anchor), not to sign-up.
- Enterprise "Contact Sales" links to `#final-cta`, which has no contact form or email; the only email is in the footer.
- No secondary conversion path (newsletter, guide download, demo booking) for buyers not ready to trial.
- No sticky/mobile CTA. No CTA instrumentation of any kind (no analytics dependency in `package.json`).
- The "Builder credibility" section is a `1fr 1fr` grid with no mobile breakpoint — the badges column collapses badly under 700px.

## 6. Technical / performance smells

- All styling is inline `style={}` objects: no hover/focus states, no media queries (grid `auto-fit` only), no reduced-motion handling, no focus-visible rings.
- Every marketing page ships its own copy of the nav and footer markup.
- `public/sitemap.xml` is hand-maintained; `lastmod` values are stale (April/July 2026) and there is no route to keep them current.
- `public/robots.txt` disallows `/dashboard/` but not the other app routes (`/chat`, `/tickets`, `/cases`, ...); harmless because Clerk 404s them, but noisy.
- Clerk's browser script (`clerk.browser.js`) loads on every marketing page. Not changed here (ClerkProvider is in the root layout and required for the app), but it is the heaviest third-party asset on the marketing surface.
- CSP `font-src 'self' data:` — Google Fonts via `next/font` are self-hosted, so fonts are fine; **any** externally-hosted font would be blocked.

## 10. Pass 2 adversarial review (2026-09-05)

Verified against a production build served locally (`next start`), Chromium at 390x844 and 1440x900, all 17 sitemap routes crawled. Defects found and fixed:

- **P0 - the header CTA was invisible on every marketing page.** `.mk a { color: inherit }` (specificity 0-1-1) beat `.mk-btn--primary { color: var(--paper) }` (0-1-0), so the primary "Start free trial" button rendered ink text on an ink background, contrast 1:1. Same bug silently hit `.mk-skip` (the skip link) and `.mk-reg__src`. Fixed by lowering the reset to `.mk :where(a)`, which lets every later single-class rule win without changing inheritance for unstyled links.
- **P1 - the pricing page contradicted the coverage claim.** `lib/data/plans.js` Starter listed "Federal + 50-state employment law context" while the matrix, hero, FAQ, llms.txt and JSON-LD all say federal + 11 states. Corrected to 11, and a test now fails if any plan feature claims a state count the jurisdiction database does not have.
- **P1 - unknown URLs redirected crawlers to sign-in.** `proxy.ts` protected everything not explicitly public, so `/anything-mistyped` returned 307 to Clerk instead of 404, and the 404 page pass 1 built was unreachable. `proxy.ts` now protects an explicit list of the `app/(app)` routes plus `/api`, and lets unmatched paths fall through to Next's 404. A test asserts the list covers every directory in `app/(app)`; `AppShell` (client redirect) and `requireRole` (every API route) remain as defence in depth.
- **P1 - metadata over budget.** Six route descriptions ran 167-212 characters and `/features` had a 61-character title; every blog post used its full headline (62-116 chars) as the `<title>`. Descriptions trimmed to <=155, `/features` title shortened, and each post now carries a `seoTitle` used only for metadata so the H1 keeps the long headline. Budgets are enforced by tests.
- **P1 - a model vendor was named in public copy.** The privacy subprocessor list and five blog bios named an AI vendor. The disclosure now names the gateway actually contracted with, the bios keep the credential without the vendor, and the test covers `content/blog/posts/` as well as the marketing pages.
- **P2 - house copy rules.** 60+ em dashes removed from rendered copy (triage feed, jurisdiction values, regulatory titles, connector descriptions, privacy and security pages, two long articles); the pricing matrix "not included" glyph is now an en dash. "world-class" removed from a comparison post.
- **P2 - copy accuracy.** The timeline step read "0:60" (now "1:00"), and the hero's secondary CTA promised "See it read a real policy" while linking to a written walkthrough (now "See how one question is handled").

Not changed, deliberately: the site has no dark-theme palette. It commits to one ink-on-paper look, sets its own background and colours explicitly, and renders byte-identically under `prefers-color-scheme: dark`, so nothing resolves wrong; adding a second palette was out of scope for a review pass.
